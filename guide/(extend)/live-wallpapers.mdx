and plays with your pointer, as Shoal's fish scatter from it. You or your coding agent can take it
from an idea to HiveHub with the `hive` command.

## What a live wallpaper is

A live wallpaper is a small web page that the app runs behind the canvas, in a sandboxed frame,
as it runs a [view](/extension-authoring). Shoal, Koi Pond, Jellyfish and Fireflies are the ones
that come with the app ([how to pick one](/appearance)). Yours ships in a
[package](/packages), and its id is `@owner/package/<folder>`.

It is a world of its own. What lives in it moves by itself, and plays with the person at the
computer through the pointer. It is told only:

- its size, and the screen's pixel ratio;
- the theme: its page and text colours, whether it is dark, and the terminals' font;
- whether to run, keep its last frame, or show one settled frame;
- the pointer over empty canvas, and clicks there.

It is told nothing of your workspace: not your agents, your tiles, their names or what they show.
It loads and fetches nothing from the network, has no permissions, never has the keyboard, and
cannot change the workspace. The two things it says back are that it speaks the protocol, and
that its first frame is up.

Like a view, its frame can still open a WebRTC connection, which no page policy in Chromium
stops, and so could send what it is told elsewhere. Install live wallpapers, like views, from
people you trust.

It is not drawn behind a view you installed, which paints its own scene, nor on the
[phone page](/phone).

## Before you start

- Hivemind 2026.10.9 or newer.
- Node 22 or newer, for `npm`.
- You know a little TypeScript or JavaScript, or your coding agent does.

  <Step title="Write the scene">
    The smallest scene that runs on the app's clock looks like this: motes that drift on a slow
    current, lean away from the pointer, and ring where you click.

    ```ts src/main.ts
    import { connectWallpaper } from "@hivemind/view-sdk";

    const wp = await connectWallpaper();
    const canvas = document.body.appendChild(document.createElement("canvas"));
    Object.assign(canvas.style, { position: "fixed", inset: "0" });
    const g = canvas.getContext("2d")!;

    let motes: { x: number; y: number }[] = [];
    const rings: { x: number; y: number; age: number }[] = [];
    let pointer: { x: number; y: number } | null = null;
    let t = 0;

    // Sharp on any screen: the canvas is the viewport times its pixel ratio.
    // As many motes as the screen holds, so a big one is as full as a small one.
    wp.on("viewport", ({ w, h, dpr }) => {
      canvas.width = Math.round(w * dpr);
      canvas.height = Math.round(h * dpr);
      Object.assign(canvas.style, { width: `${w}px`, height: `${h}px` });
      motes = Array.from({ length: Math.round((w * h) / 12000) }, () => ({ x: Math.random() * w, y: Math.random() * h }));
    });
    // The pointer over empty canvas, or gone from it.
    wp.on("pointer", ({ x, y, over }) => { pointer = over ? { x, y } : null; });
    // A click on empty canvas.
    wp.on("click", ({ x, y }) => { rings.push({ x, y, age: 0 }); });

    wp.animate({
      step(dt) {
        t += dt;
        const { w, h } = wp.viewport;
        for (const m of motes) {
          m.x = (m.x + 12 * dt + w) % w;                    // a slow current of its own
          m.y = (m.y + Math.sin(t + m.x / 90) * 8 * dt + h) % h;
          if (!pointer) continue;
          const dx = m.x - pointer.x, dy = m.y - pointer.y, d = Math.hypot(dx, dy);
          if (d > 0 && d < 120) { m.x += (dx / d) * 60 * dt; m.y += (dy / d) * 60 * dt; }
        }
        for (const r of rings) r.age += dt;
        while (rings.length && rings[0]!.age > 1.5) rings.shift();
      },
      draw() {
        const { w, h, dpr } = wp.viewport;
        const { dark, mono } = wp.look;
        g.setTransform(dpr, 0, 0, dpr, 0, 0);
        g.globalAlpha = 1;
        g.fillStyle = dark ? "#0b1d26" : "#e4f1ef";         // its own water, dark or light
        g.fillRect(0, 0, w, h);
        g.fillStyle = dark ? "#8fd3d0" : "#2d6f78";
        g.font = `14px ${mono}, monospace`;
        for (const m of motes) g.fillText("*", m.x, m.y);
        for (const r of rings) {
          g.globalAlpha = 1 - r.age / 1.5;
          for (let a = 0; a < 6.28; a += 0.4) g.fillText("~", r.x + Math.cos(a) * r.age * 80, r.y + Math.sin(a) * r.age * 50);
        }
      },
    });
    ```

    To have your coding agent write yours, put your idea at the top of `PROMPT.md` and hand it the
    file.

## What it is told, and what it says

The app and the wallpaper talk over one message port. Every message is a JSON object with a
`type`, checked on both sides. `@hivemind/view-sdk` speaks it for you: `connectWallpaper()`
waits for the app, and `wp.on(…)` gives you each message below. `wp.viewport`, `wp.look` and
`wp.mode` hold the latest, and a new listener for one of those three is called at once with it.

| The app sends | Holds | When |
|---|---|---|
| `hello` | `{ protocol, viewport, look, mode }`: everything below at once | once, after it says `ready` |
| `viewport` | `{ w, h, dpr }`: its size in CSS pixels, and the screen's pixel ratio | the window is resized or moves to another screen |
| `look` | `{ page, text, dark, mono }`: the theme's page and text colours as `#rrggbb`, whether the theme is dark, and the terminals' font as a CSS font list | the theme or the code font changes |
| `mode` | `run`, `hold` or `still` | see [the clock](#the-clock) |
| `pointer` | `{ x, y, over }`: the pointer over empty canvas, or gone from it (`over` is `false`) | at most once a frame while it moves there, and once as it leaves |
| `click` | `{ x, y }`: the main button pressed on empty canvas | as the press starts |

| It sends | Holds | The SDK sends it |
|---|---|---|
| `ready` | `{ protocol: 2 }` | in `connectWallpaper()` |
| `drawn` | nothing: the first frame is up, and the app shows the layer | after the first frame of `animate`, or with `wp.drawn()` |

Each message carries its own keys and no others. Empty canvas is the canvas itself, not a tile, a
frame or a panel over it. The pointer leaves it when it goes over one of those, out of the window,
or when the window loses focus. A touch screen sends no pointer, but a tap is a click. The same
press also reaches the canvas, so a drag that starts there still pans it.

## The clock

`wp.animate({ step, draw, settle })` runs your scene on the clock the built-in scenes use:

- `step(dt)` moves the scene on by 1/60 of a second, as many times as the time that passed needs
  (at most four a frame; a busy computer drops the rest). The scene moves at the same speed
  whatever the frame rate.
- `draw(dt)` draws it as it is, at most 30 times a second. Characters read smooth at 30, and it
  costs half of 60. `animate(scene, { fps: 60 })` asks for more.
- `settle()`, if you give it, puts everything where it would be after a while. Without it, the
  clock runs 360 steps.

The mode decides what runs:

| Mode | When | What the clock does |
|---|---|---|
| `run` | the window is shown and focused, whether or not you are using it | steps and draws |
| `hold` | the window is hidden or not focused, or something covers the canvas: **Settings**, or a tile made fullscreen | nothing. It draws one frame again only when the size or the look changes. No pointer or click comes |
| `still` | the person turned off **Animation**, or the computer asks for reduced motion | one settled frame: `settle()` and one draw. Again only when the size or the look changes |

Its first frame is drawn at once, whatever the mode. Never start a timer or a
`requestAnimationFrame` loop of your own: while held, a wallpaper that keeps drawing spends the
battery on a window nobody sees.

When the computer asks for more contrast or less transparency, the app draws no live wallpaper
at all.

## Play with the pointer

The pointer is the one thing a person does to the scene, and the scene's life should notice it,
calmly. The built-in scenes show how: in Shoal small fish scatter from the pointer, and in Koi
Pond a click drops pellets that the nearest koi race to eat. What each one does is in
[Change how Hivemind looks](/appearance).

- Let the pointer nudge, draw or scare what is near it, by a little and over a short reach. The
  rest of the scene goes on as before.
- When `over` is `false`, let whatever followed or fled the pointer go back to its own life.
- A click is brief: a ripple, food dropped, a scatter, gone within a second or two.
- Answer both in `step`, so a held or still scene stays as it is.

## Colours

- **Its own colours.** Draw the scene in a palette of its own, one version for a dark theme and
  one for a light one, picked by `dark`, as each built-in scene does.
- **The theme's colours.** `page` and `text` are there to draw in, or to lean your ground toward,
  so the scene sits with any theme.
- **Characters.** `mono` is the terminals' font, as a CSS font list. It is the person's choice and
  may not be on this computer, so end it with a fallback: `` `${mono}, monospace` ``.
- **Panel text over it.** With glass on, the Layers panel and the toolbars are frosted glass, and
  their text sits over your scene. Over a live wallpaper the Layers panel is clearer than usual,
  a third of its tint. Keep the scene dark enough on a dark theme, and light enough on a light
  one, that the text reads over every part of it. The hivemind-live-wallpaper skill in your
  package's `.claude/skills/` says how to test it.

## hivemind-wallpaper.json

| Field | Needed | Takes |
|---|---|---|
| `protocol` | yes | `2` |
| `name` | yes | up to 60 characters: the name in **Settings → Appearance** |
| `entry` | yes | an `.html` page or a `.js` script inside the folder, usually `dist/main.js`. A script is put in a page of the app's own |
| `description` | no | one sentence, up to 200 characters, shown under its name |
| `preview` | no | a PNG, JPEG or WebP picture inside the folder (`.png`, `.jpg` or `.webp`), up to 512 KB, shown in the picker |

```json
{
  "protocol": 2,
  "name": "Pond",
  "entry": "dist/main.js",
  "description": "Koi under lily pads that drift toward your pointer.",
  "preview": "preview.png"
}
```

The folder's name is the last part of its id: lowercase letters, digits and single dashes. A
wallpaper whose `protocol` is `1` is refused at install and by `hive plugins check`: build it
again with the SDK the app serves, and set `protocol` to `2`.

## Ship it in a package

A live wallpaper always comes in a package, which names it in `hivemind-package.json`:

```json
"wallpapers": [{ "path": "wallpapers/pond" }],
"startup": { "wallpaper": "@you/pond/pond" }
```

`startup.wallpaper` names one of the package's own wallpapers. Once the package is installed and
on, the app offers it as the background, once per package, as `startup.view` offers a view. The
person chooses; nothing switches without them.

A package may hold a live wallpaper alone, or beside a view and a theme that go with it.
Archipelago (`@dip497/archipelago` on HiveHub) ships its view with its widgets and a theme, and
offers the view with `startup.view`; a wallpaper is offered the same way. Give `startup` both a
view and a wallpaper, and the app offers both. The rest of what a package holds, and how to
update and roll it back: [Packages](/packages).

## What turns it off

The app turns a live wallpaper off for the session, shows a notice, and draws the plain
background instead, when it:

- sends 8 messages that are malformed;
- sends more than 120 messages a second;
- asks for a newer protocol than this Hivemind speaks;
- takes the keyboard (focuses anything in its frame);
- uses 60% of a CPU core for six seconds.

The scene runs in a process of its own, so it never slows your terminals, but a busy one is still
turned off. Measure what a frame costs: the hivemind-live-wallpaper skill in your package's
`.claude/skills/` says how.

## Limits

| What | Most |
|---|---|
| Live wallpapers in a package | 8 |
| A preview picture | 512 KB |
| Frames a second | 30, or what `fps` asks, up to 60 |
| Waiting for the app | `connectWallpaper()` gives up after 10 seconds |

## Commands

```bash
hive plugins new wallpaper <name>              # a package holding a working wallpaper, with PROMPT.md
hive plugins new wallpaper <name> --in <pkg>   # one more in a package you have
hive plugins check <package>                   # the manifests, and the wallpaper loaded once
hive plugins install <package>|@owner/package
hive config set appearance.wallpaper.kind '"@owner/package/name"'
hivehub publish <package>
```

The `hive plugins` commands are in the [CLI reference](/cli#plugins).
