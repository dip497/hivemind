A <Tooltip tip="A plugin that adds a kind of tile, such as a pull request panel. It runs with your access, so it starts switched off." cta="Glossary" href="/glossary#tool">tool</Tooltip> adds a kind of <Tooltip tip="One thing in a frame: an agent, a terminal, the Code tile, a browser or a tool." cta="Glossary" href="/glossary#tile">tile</Tooltip>. Write one when you want a panel beside your agents that shows something from your project.

The Browser, Issues and the Code tile are tools that come with the app.

<Warning>
**A tool runs with your access.** It runs inside the app with your files, programs and logins.
So a tool you add starts switched off, and you turn it on yourself. Turn on only tools whose author
you trust. If one breaks the app, start it with `HIVEMIND_SAFE_MODE=1 hivemind`: no added tool
loads.
</Warning>

## Try one

1. Install a tool from HiveHub:

   ```bash
   hive plugins install @dip497/worktrees
   ```

   Check: it prints `installed @dip497/worktrees` and says it is off.
2. Switch it on:

   ```bash
   hive plugins enable tool:@dip497/worktrees
   ```
3. Open its tile:

   ```bash
   hive ctl plugin open tool:@dip497/worktrees
   ```

   Check: a tile opens that lists every git worktree of the project.

Or do it in **Settings → Plugins**, on the **HiveHub** tab: pick a tool, install it, and turn it on
on its page.

## Write one

### Before you start

- Hivemind is installed and open on a project that is a git repository.
- You know a little JavaScript and React.

<Steps>
  <Step title="Start the tool">
    ```bash
    hive plugins new tool branch
    ```

    Check: it prints `started tool plugin @<your login>/branch`. If it asks whose it is, add
    `--owner <your GitHub login>`.
  </Step>
  <Step title="Install it and switch it on">
    ```bash
    cd branch && hive plugins install . && hive plugins enable tool:@<your login>/branch
    ```

    Check: `hive plugins list` shows `tool:@<your login>/branch` as on.
  </Step>
  <Step title="Open its tile">
    Open it from the frame's **Open** menu, or run `hive ctl open-tool @<your login>/branch`.

    Check: a tile shows **Branch:** and the project's current git branch, with a **Refresh** button.
  </Step>
  <Step title="Read the code">
    The starter's `index.js` draws the tile with the app's own React. It runs `git` through
    `host.run`, in the tile's folder:

    ```js index.js
    import React, { useEffect, useState } from "hm-plugin://host/react.js";
    import { Button } from "hm-plugin://host/sdk.js";

    const h = React.createElement;

    function Tile({ tile, host }) {
      const [branch, setBranch] = useState("…");
      const refresh = () => host.run("git", ["branch", "--show-current"]).then((r) => setBranch(r.stdout.trim() || "(no branch)"));
      useEffect(() => { void refresh(); }, []);
      return h("div", { style: { padding: 16, display: "grid", gap: 8 } },
        h("h3", { style: { margin: 0 } }, tile.name),
        h("p", null, "Branch: ", h("code", null, branch)),
        h(Button, { size: "sm", variant: "outline", onClick: refresh }, "Refresh"));
    }

    export default { tiles: { "you-branch": Tile } };
    ```

    The default export maps each tile kind in `hivemind-tool.json` to the component that draws it.
  </Step>
  <Step title="Change it">
    Make the button show the last commit too. Replace the `refresh` line with:

    ```js
    const refresh = () => host.run("git", ["log", "-1", "--format=%D: %s"]).then((r) => setBranch(r.stdout.trim()));
    ```

    Install it again with `hive plugins install .`. Changed code arrives switched off, so switch it
    on again with `hive plugins enable tool:@<your login>/branch`, then press **Refresh** in the tile.

    Check: the tile shows the branch and the last commit's subject.
  </Step>
</Steps>

### Check it worked

- `hive plugins list` shows the tool on, with no problem.
- Its tile opens from the frame's **Open** menu.

### If it didn't

| You see | Do this |
|---|---|
| The tile is missing from **Open** | `hive plugins enable tool:<id>`; a tool you add starts off. A tool with `needsRepo` only shows in a frame with a git repository. |
| The app misbehaves after you turned a tool on | Start it with `HIVEMIND_SAFE_MODE=1 hivemind`, then switch the tool off on its page. |
| Something else | [Troubleshooting](/troubleshooting) |

## Tool reference

### The manifest

```json hivemind-tool.json
{
  "id": "@acme/prs",
  "name": "Pull requests",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "One line, shown in Settings.",
  "category": "git",
  "entry": "index.js",
  "permissions": ["workspace:spawn"],
  "settings": [
    { "id": "state", "label": "Show", "type": "choice", "values": ["open", "all"], "default": "open" }
  ],
  "tools": [
    {
      "key": "prs", "label": "Pull requests", "description": "What its tile shows.",
      "tileKind": "acme-prs", "size": { "width": 1100, "height": 760 },
      "needsRepo": true, "singleton": true, "glyph": "⇅", "icon": "icon.svg"
    }
  ]
}
```

| Field | Means |
|---|---|
| `id` | `@owner/name`; `@hivemind/` is kept for the app's own |
| `tools[]` | one entry per kind of tile. `needsRepo` hides it in a frame with no repository. `singleton` focuses the open one instead of opening another. |
| `icon` | an `.svg` in the folder (32 KB at most); without one, `glyph` is shown |
| `permissions`, `settings` | the same as a view's ([Write a view](/extension-authoring#permissions)) |
| `"commands"` | what an agent can run while a tile of the tool is open |
| `"category"` | where it is grouped in the Add menu and on HiveHub |
| `"skills"` | agent skills it ships: see [Agent skills](#agent-skills) |

### What a tile gets

| Prop | What it is |
|---|---|
| `tile` | `{ id, kind, name, frameId }` |
| `hm` | the client a view has (`@hivemind/view-sdk`): frames, tiles, agents' status and events, commands, its settings, and its saved state, kept per tile (`hm.hello.layout`, `hm.setLayout`). Each is held to the permissions the manifest declares. |
| `host` | what only a tile has: `repoPath`, `cwd`, `run(bin, args, { maxAgeMs, stdin })` (see [Running programs](#running-programs)), `openFile(path)` in the frame's Code tile, `openUrl(url)` in the frame's browser, `call(command, args)` to its own [service](#a-service-that-keeps-running) |
| `selected` | it has the person's focus |

A tile imports the app's own React and parts from `hm-plugin://host/`: `react.js`,
`react-jsx-runtime.js`, `sdk.js` and `ui.js`. It bundles none of them.

`sdk.js` has `Button`, `PatchView` (a diff), `Markdown`, `Loading`, `Frame` (a page from a server
on this machine) and `useTileState(hm, key, initial)`, which keeps a value with the tile across
restarts. `ui.js` is the
app's whole UI kit (`Button`, `Input`, `Dialog…`, `DropdownMenu…`, `Switch`, `toast`, …). The
built-in Issues tile (`apps/desktop/tools/issues` in the repository) is the fullest example.

Reach the app only through these, never `window.hive`.

### Ids, opening and reinstalling

A tool package's id is `@owner/name`. Each tool in it has a full id, `@owner/name/<key>`:
`hive plugins list --kind tool` prints it.

```bash
hive ctl open-tool @acme/prs                       # the package's tool, when it has one
hive ctl open-tool @acme/prs/prs                   # by its full id; needed when it has several
hive ctl open-tool @acme/prs --state '{"tab":"open"}'   # the tile's first state
```

`--state` is a JSON object: each key is what `useTileState(hm, key, initial)` reads when the tile
first draws.

Installing a tool again with the same code, byte for byte, keeps it on or off as it was. Changed
code is switched off, since turning it on trusted the code that was there: switch it on again
with `hive plugins enable tool:<id>`. The install says which.

### Running programs

`host.run(bin, args, { maxAgeMs, stdin })` runs a program and answers `{ code, stdout, stderr }`.

- `bin` is a program's name, found on the app's `PATH`, which comes from your login shell. A
  folder on `PATH` inside the tile's own folder is skipped.
- It runs in the tile's folder, without a shell: `args` reach it as they are, with no globs or
  pipes. On Windows a `.cmd` or `.bat` shim is refused, since only a shell can run one.
- It is stopped after 60 seconds, and when it writes more than 10 MB.
- `maxAgeMs` (up to 5 minutes) answers the same call from a cache while it is that fresh.
- `stdin` is text written to its input.

### Show a server on this machine

A tool can show a page its own local server serves, such as a dev server or a dashboard. Use
`Frame` from `sdk.js`:

```js
import { Frame } from "hm-plugin://host/sdk.js";

h(Frame, { src: "http://127.0.0.1:5173/", title: "Dev server" });
```

Only `http://127.0.0.1:<port>` and `http://localhost:<port>` can be shown; any other address is
blocked, and the tile stops and says so. `Frame` runs the page's scripts, forms and popups, and
never lets it move the app's window.

### Look at it, and see what broke

```bash
hive ctl tile look <tile> --json   # a picture of the tile, its state and its console
hive ctl plugin list --json        # each plugin's state: starting, ready or failed, with why
```

`tile look` brings the tile into view, waits until its code has drawn, and saves a PNG of it. It
answers the tool's state, whether it drew, and the last 100 lines its code wrote to the console.
When something is drawn over the tile, such as a pinned tile, a dialog or a notification, it
refuses with `OCCLUDED` and names it; move it, or wait for the notification, and look again.

When the tool's code throws an error nothing catches, a promise of its fails unheard, or the app
blocks something it loads, its tile stops and shows why, and `plugin list` reads it as `failed`
with that reason.

### Pointer and keys in a tile

What the canvas does with input over a tool's tile, so your tile can count on it:

| Input | What happens |
|---|---|
| Left click and drag | Yours. The tile moves only by the bar the app draws on it. |
| Right click | Yours: `contextmenu` reaches your tile, and the app shows no menu of its own. On a tile that is not selected, dragging with the right button pans the canvas instead. |
| Middle button | Pans the canvas, always. Your tile does not see it. |
| Wheel | Yours first. When the tile is not selected and nothing under the pointer scrolls, it also pans the canvas. Ctrl or ⌘ with the wheel zooms the canvas and never reaches your tile. |
| Keys | Yours while focus is in your tile, but for the app's own shortcuts (such as Ctrl+Tab, Ctrl+1 to 9 and Ctrl+,), which the app takes first. |
| Cursor | Yours: set `cursor` on any element you draw, inside a shadow root too. Where you set none, it is the normal pointer. |

### Commands agents can run

Declare them in `hivemind-tool.json`, and answer them in the tile:

```json
"commands": [{ "name": "list", "description": "Every worktree, with its branch and what is not committed." }]
```

```js
useEffect(() => hm.onCommand("list", () => trees), [hm, trees]);
```

`hive ctl plugin call @dip497/worktrees list` prints what the handler returns. It works while a tile
of the tool is open. With two open, name one with `--tile`. With none open, the tool's
[service](#a-service-that-keeps-running) answers it, if it serves that command: under `hive host` too.

### A service that keeps running

A tool can bring a program the app keeps running while the tool is on: an orchestrator, a
dashboard, a watcher. It drives workspaces through the [API](/api), with its own token.

```json
"service": { "command": ["node", "service.js"], "role": "agents" }
```

`role` is one of the [roles](/api-tokens). Once switched on, the service waits until you
pick the workspaces it may drive, on the tool's page. Where `hive host` runs it, use
`hive plugins workspaces tool:<id> <folder>`. It then starts with these variables:

| Variable | What it holds |
|---|---|
| `HIVE_DRIVE_SOCK` | where it connects |
| `HIVE_DRIVE_TOKEN` | its token: the first line it sends is `{"hello": {"token": …, "workspace": …}}` |
| `HIVE_WORKSPACES` | the folders it may drive, separated as in `PATH` |

It restarts after a crash (after 1 s, then 2, 4… up to a minute). It stays stopped after a clean
exit, or when its token is revoked. It should exit when its standard input closes. Its output is
on its page; it is written as printed, so never print a token.

`node` in its command needs no Node.js on the machine: the app runs it with its own runtime.
`hive host` uses the `node` on `PATH`, and says so when there is none.

What a service asks of its own tool, on its connection:

| Call | What it does |
|---|---|
| `plugin.options` | `{values, secrets}`: what the person set the tool's `settings` to, and which of its secrets are set. After it asks, each change comes as the event `options.changed`; a change does not restart it. |
| `secret.get(name)` | one of the tool's `secret` settings, or null. Never another plugin's. |
| `plugin.serve` (notice) | `[{name, description}]`: the commands it answers. Each call comes as the event `plugin.called {call, command, args}`; it answers with the notice `plugin.answer(call, {result} \| {error: {code, message}})`, within 30 s. |
| `issue.create`, `issue.update`, `issue.setState`, `issue.comment` | at the `edit` role: written into the issue's activity as `@owner/name (service)`. |

The tool's own tiles reach its service with `host.call(command, args)`: the answer, or an error
saying why there is none (the service is off, or not switched on for this workspace). A tile reaches
only its own tool's service. A service that drives several workspaces answers on the connection it
served last, so a tile names its own in the arguments (`{ ...args, workspace: host.repoPath }`).

Every write to the workspace's issues, from the app, `hive` or an agent, comes as the event
`issue.changed {id, root, change, fields, by}`.

A setting of type `secret` (tools only) is an API token or a password. You type it on the tool's
page, where it is never shown again, or pipe it in: `printf %s "$TOKEN" | hive plugins set
@acme/jira token`. It is kept in the system keychain, or, where there is none (`hive host`, a Linux
with no keyring), in `secrets.json` beside `settings.json`, readable by you alone. `settings.json`
says only that it is set, and the tool's tiles never see it.

### Agent skills

A tool can teach agents how to use it. List skill folders in the manifest, each holding a
`SKILL.md` whose frontmatter `name` is the folder's name:

```json
"skills": ["skills/prs"]
```

Hive copies each one to `.claude/skills/<name>/` in every workspace the tool is on for, when you
run `hive init` or `hive add skill`, and before the app starts an agent there. A tool with a
service is on for the workspaces its service drives, and their linked worktrees.

- **It stays out of git.** Each folder hive writes is listed in the clone's `.git/info/exclude`,
  never in your `.gitignore`, so it is never committed by accident.
- **It follows the tool.** An update replaces it, and switching the tool off or removing it takes
  it away, the next time hive installs skills there.
- **Your edits are kept.** A copy you changed is left as it is, and `hive add skill` says so.
  Delete the folder to get the tool's copy back, or its `.hive-plugin` file to make it yours.
- **Your skills are never touched.** If a skill hive did not write already has that name, the
  tool's skill is not installed, and `hive add skill` names it.

A skill can have at most 32 files and 512 KB, with no links. It cannot take the name of one of
hive's own skills. `hive plugins check` reports a skill that breaks these rules.

### On a shared canvas

A guest sees a tool's tile if they have the same tool switched on. A tile's programs run on the
computer of the person looking at it.

### Commands

```bash
hive plugins new tool <name> [--dir folder]   # a starter, with PROMPT.md and its types
hive plugins check <folder>                    # its types, its manifest, and each tile drawn once, with file:line
hive plugins api --kind tool                   # tile, host and hm, as declared
hive plugins install <folder>|@owner/name       # new or changed code off: hive plugins enable @owner/name
hive plugins list --kind tool                  # each tool, and the full id of each of its tiles
hive plugins remove @owner/name
```
