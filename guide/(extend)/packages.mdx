title: "Packages"
description: "Put your tools, widgets and views in one package, check it, install it and publish it on HiveHub, all from the hive command."

A package puts your own tools, widgets and views in one box that installs, switches on, updates
and rolls back as one. You or your agent can write one from the `hive` command alone, from the
first folder to its page on HiveHub.

<AgentPrompt description="Paste this into your coding agent to build a package of your own Hivemind tools, widgets and views." page="packages">{`
Build a Hivemind package that does what I describe, using the hive command.

1. Run \`hive plugins new package <name>\`. If it asks for an owner, ask me for my GitHub login and pass \`--owner <login>\`. Read the PROMPT.md it writes in the new folder: it holds the whole guide.
2. Add each member I asked for: \`hive plugins new tool <name> --in <package>\`, \`hive plugins new widget <name> --in <package>\` or \`hive plugins new view <name> --in <package>\`. Read each member's PROMPT.md before writing its code. For a view, run \`npm install\` in its folder once.
3. Run \`hive plugins check <package>\` after each change, and fix every problem it reports at its file and line until it says ok.
4. Run \`hive plugins install <package>\`. If it says the package is off, tell me and ask me to switch it on with \`hive plugins enable <package id>\`: only I decide to trust code.
5. Open each member with \`hive ctl plugin open <kind>:<id>\`, and look at a tool's tile with \`hive ctl tile look <tile>\`.

At the end, tell me what the package holds and what each member asks for. Do not publish it unless I ask.
`}</AgentPrompt>

<Diagram name="packages-one-box" caption="A package is one box" />

- A **package** is one folder. Its `hivemind-package.json` names its **tools**, **widgets**,
  **views** and **agent presets**, each tool, widget and view in a folder of its own with its
  own manifest. Every member's id has the package's owner: `@you/<name>`.
- Package → **this machine**: `hive plugins install` puts the whole box in, with one switch, one
  version and a rollback.
- Package → **HiveHub**: `hivehub publish` lists the whole box, with every member and what it
  asks for.

Which packages arrive switched off, and which updates need your trust again, are in
[Plugins](/plugins#packages).

<Steps>
  <Step title="Start the package">
    ```bash
    hive plugins new package kit
    ```

    It writes `kit/` with a `hivemind-package.json` that holds nothing yet, a `README.md`, and a
    `PROMPT.md` to hand your coding agent. Its owner is the GitHub login `gh` is signed in as,
    or the one you pass with `--owner`.
  </Step>
  <Step title="Add members">
    Start each member inside the package. It is named in `hivemind-package.json` for you, with
    the package's owner:

    ```bash
    hive plugins new tool prs --in kit       # kit/tools/prs
    hive plugins new widget dog --in kit     # kit/widgets/dog
    hive plugins new view board --in kit     # kit/views/board, named by its built dist/
    hive plugins add ../counter --to kit     # one you already wrote, copied into kit/widgets/counter
    ```

    `add` refuses a plugin whose id is not yours (`@you/<name>`), and changes nothing. Each new
    member has its own `PROMPT.md` with the guide of its kind: [tools](/tool-plugins),
    [widgets](/widgets) or [views](/extension-authoring). For a view, run `npm install` in its
    folder once.
  </Step>
  <Step title="Check it">
    ```bash
    hive plugins check kit
    ```

    It checks `hivemind-package.json`, then every member with that member's own check: its
    types, its manifest, and its code drawn once. A view is built first. Each problem has its
    file and line: a member's in its own folder, and a misspelt member path or a member with
    someone else's id at the line of `hivemind-package.json` that names it.

    Check: it ends with `ok: package @you/kit`. `--json` gives the same report to an agent.
  </Step>
  <Step title="Install it">
    ```bash
    hive plugins install ./kit
    ```

    It prints the package and each member it holds, with what each asks for. Install again after
    each change. `--dry-run` shows what would change, member by member, and installs nothing.
  </Step>
  <Step title="Switch it on">
    A package that holds a tool or an agent preset arrives off. Switch it on once you trust what
    it runs:

    ```bash
    hive plugins enable @you/kit
    hive ctl plugin open tool:@you/prs     # or widget:… or view:…
    hive ctl tile look <tile>              # what a tool drew, and what its code logged
    ```

    In the app, it is one row in **Settings → Plugins**, with one switch.
  </Step>
  <Step title="Update it">
    Change a member, raise `version` in `hivemind-package.json`, check, and install again. When a
    change needs your trust again, the package goes off, and the install lists what changed.
  </Step>
  <Step title="Roll back">
    ```bash
    hive plugins rollback @you/kit
    ```

    It puts back the version in use before the last update, switched on or off as it was.
  </Step>
  <Step title="Publish it">
    Commit the package folder, with each view's `dist/`, and push it to GitHub. Then:

    ```bash
    hivehub publish kit
    ```

    It shows the package, each member, where its code runs and what it asks for, and publishes
    when you answer `y`. Anyone can then install it with `hive plugins install @you/kit`. Getting
    the `hivehub` command and signing in are in [Publish to HiveHub](/publish-to-hivehub).
  </Step>
</Steps>

Every command on this page is in the [CLI reference](/cli#plugins).
