## What you'll learn

- How to start a view from the starter and switch the window to it.
- How a view hears the workspace change and shows each agent's status.
- How to rebuild it and see the change.

## Before you start

- Hivemind is installed and open on a project with a few tiles. See [Install and run your first agent](/getting-started).
- Node 22 or newer, for `npm`.
- You know a little TypeScript or JavaScript.

<Steps>
  <Step title="Start the view">
    ```bash
    hive plugins new view pulse
    ```

    Check: it prints `created @<your login>/pulse`. If it asks for an owner, add
    `--owner <your GitHub login>`.

    ```text
    pulse/
      hivemind-view.json   the view's name, id, version and permissions
      index.html           the page, which loads ./main.js
      src/main.ts          your code
      PROMPT.md            the whole contract, for a coding agent
      dist/                what you install and publish, once built
    ```
  </Step>
  <Step title="Build and install it">
    ```bash
    cd pulse && npm install
    npm run dev
    ```

    Check: the last line says `installed @<your login>/pulse`. `npm run dev` builds `dist/` and
    installs it in one go.
  </Step>
  <Step title="Switch to it">
    Open the view menu in the toolbar (it shows **Canvas**) and pick **Pulse**.

    Check: the window shows **Pulse** and one row per tile, each with a dot for its status. Press a
    row and Hivemind selects that tile.
  </Step>
  <Step title="Read the code">
    `src/main.ts` connects, follows your theme, and redraws when tiles change:

    ```ts src/main.ts
    import { applyThemeVars, connect, statusTone } from "@hivemind/view-sdk";

    const hm = await connect();
    applyThemeVars(hm);

    const list = document.querySelector("ul")!;
    let unsubscribe: (() => void)[] = [];

    hm.on("structure", ({ tiles }) => {
      for (const off of unsubscribe) off();
      list.replaceChildren();
      unsubscribe = tiles.map((tile) => {
        const dot = Object.assign(document.createElement("span"), { className: "dot" });
        const button = document.createElement("button");
        button.append(dot, tile.name);
        button.onclick = () => hm.commands.selectTile(tile.id);
        const item = document.createElement("li");
        item.append(button);
        list.append(item);
        return hm.subscribeStatus(tile.id, (s) => { dot.dataset.tone = statusTone(s); });
      });
    });
    ```

    `structure` comes again whenever frames or tiles change. The app serves `@hivemind/view-sdk`
    to every view, so your bundle leaves it out.
  </Step>
  <Step title="Change it">
    Add this line inside the `structure` handler, after `list.replaceChildren();`:

    ```ts
    document.querySelector("h1")!.textContent = `${tiles.length} tiles`;
    ```

    Run `npm run dev` again.

    Check: the heading now counts your tiles. Open a terminal and the count goes up.
  </Step>
</Steps>

## What you did

- You started a view with `hive plugins new view` and installed it with `npm run dev`.
- You switched the window to it from the toolbar's view menu.
- You read the workspace with `hm.on("structure")` and each agent's status with `hm.subscribeStatus`.

## View reference

### What a view can use

Check `hm.supports("<feature>")` before using a newer feature.

| Need | Call |
|---|---|
| Put live terminals in your layout | `hm.setSurfaceRects(...)` (`surfaces`) |
| Save your layout (64 KB, per workspace) | `hm.setLayout(blob)` |
| An agent's status as it changes | `hm.subscribeStatus(tileId, (status, info) => …)` |
| What happens: replies, waits, closes | `hm.onEvents(["turn", "needsInput"], cb)` |
| How busy a terminal is (0 to 3) | `hm.activity(tileId, cb)` |
| A day's history per tile | `await hm.history("2026-09-23")` |
| Installed agents, past sessions | `await hm.agents()`, `await hm.sessions("claude", frameId)` |
| Start an agent | `hm.commands.spawnAgent(agent, frameId, { prompt, resume })` |
| Suggest a prompt (the person confirms) | `await hm.prompt(tileId, "run the tests")` |
| Who else is here | `hm.onParticipants(cb)` (`participants`) |
| The canvas's widgets | `hm.onWidgets(cb)`, `hm.pressWidget(id, action)` (`widgets`) |
| Issues | `hm.onIssues(cb)`, `hm.issues.read(id)`, `create`, `update`, … (`issues`) |
| Its settings | `hm.settings`, `hm.on("settings", cb)` (`settings`) |
| Draw your own toolbar | `"toolbar": "off"`, then `hm.commands.openHostMenu("views", rect)`, `"add"`, `"appearance"` or `"settings"` opens the app's own (`hostMenu`) |
| Messages from your scripts | `hm.onCustom("ci.*", cb)`, sent by `hive ctl view emit ci.build '{…}'` |

Each tile in `structure` carries its `icon` (an SVG in `currentColor`) and its `agent`. Each frame
carries its `folder`, `branch`, `parentId` (a worktree under its project) and `machine` when it
runs on another computer.

A view never reads an agent's replies or terminal text, and never answers its permission
questions. Every prompt a view writes opens a dialog showing the full text, with **Cancel** focused.

### Permissions

A view declares its permissions in `hivemind-view.json`. An unknown one is refused at install.
Selection and focus need none.

| Permission | Allows |
|---|---|
| `workspace:spawn` | start tiles, agents and frames |
| `workspace:close` | close tiles |
| `workspace:edit` | rename tiles, pick a frame's folder |
| `workspace:prompt` | `prompt`, and `spawnAgent` with a prompt |
| `workspace:sessions` | `sessions`, and `spawnAgent` with `resume` |
| `workspace:widgets` | press and click widgets |
| `workspace:issues` | read and change issues |

### Manifest fields

| Field | Does |
|---|---|
| `id`, `name`, `version` | its id in your GitHub scope (`@you/name`), its name, its version |
| `"description"` | one line under its name wherever views are listed, at most 200 characters |
| `"icon"` | an `.svg` in the view's folder (`"icon.svg"`), drawn in one colour like the app's icons, at most 32 KB |
| `entry` | the page to load, usually `index.html` |
| `protocol` | the view protocol it speaks: `1` |
| `permissions` | what it may do (above) |
| `"settings"` | fields the app draws on the view's Settings page: `boolean`, `number`, `text`, `choice` |
| `"commands"` | what an agent can run in it (`hm.onCommand(name, handler)`), optionally with `"keys": "mod+alt+k"` |
| `"toolbar"` | `"top"`, `"bottom"` (the default), `"hidden"` or `"off"` |
| `"widgets": "left"` | start widget cards down the left edge over the view instead of the right, for a view that keeps its own panels on the right; a card the person moved stays put |
| `"layout": "personal"` | keep the layout per person instead of shared |
| `"layers": true` | show the app's Layers panel beside the view |
| `"phone": true` | offer it on the phone page; use `hm.device.compact` and `hm.device.touch` |
| `"category"` | where it is grouped in the Add menu and on HiveHub |
| `"description"` | what it shows, in one line: the line on its card on HiveHub |

### The sandbox

The page runs on its own `hm-view://<id>` origin with a strict content policy: no `window.hive`,
no Node, no network, no inline scripts. Malformed messages, floods or runaway CPU switch it off for
the session and return you to the canvas.

- Name your files relatively (`./main.js`): in a browser tab the app serves views under a path.
- Draw on change, and stop work while `document.hidden`.
- Test without the app with `fakeHost()` from `@hivemind/view-sdk/testing`.

### Commands

```bash
hive plugins new view <name> [--dir folder]   # a starter, with PROMPT.md
hive plugins check <folder>                   # its types, its manifest, and its page built and loaded once, with file:line
hive plugins install <folder>|@owner/name
hive plugins list --kind view                 # installed views, and why any fails to load
hive plugins remove <id>
```
