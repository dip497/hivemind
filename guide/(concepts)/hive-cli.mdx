`hive` is one command for you and your agents. Most of it works alone: issues, plugins,
machines, your network. `hive ctl` drives a running workspace: the app, or `hive host` on a
server. An agent in a tile uses the same `hive ctl` you type.

<AgentPrompt description="Paste this into your coding agent to check that hive can reach your workspace." page="hive-cli">{`

<Diagram name="drive-sockets" caption="Two local sockets" />

- **hive ctl** and **your program** → **drive socket** (`drive.sock`): a hello with a token, then calls. The app or `hive host` checks the token's role. See [API](/api).
- **Agent hook** → **control socket** (`hcp.sock`): one `agent.event` each time the agent starts a turn, asks, or finishes.
- The background process owns the control socket, works out the agent's state, and passes each event on to the app or host (`hcp-host.sock`).
- `hive ctl report` and `hive ctl inbox` use the control socket too.
- Like the drive socket, the control socket opens only for your user: a file with mode 0600, or a named pipe on Windows.

## Inside a tile

Hivemind starts each agent with `HIVEMIND_TILE` set to its tile's id, and a token for that tile.
So `hive ctl` in a tile acts as that agent: a worker it spawns is its own, and `hive ctl report`
answers its lead. The variables are in [Environment variables](/environment-variables).
