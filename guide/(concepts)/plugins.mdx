A <Tooltip tip="Something you add to Hivemind: an agent, a view, a widget or a tool." cta="Glossary" href="/glossary#plugin">plugin</Tooltip> adds something to Hivemind. Your agents can make one, install one and open one while they work. The **Windows** view and the **Issues** tool ship with the app as plugins too.

- **View**: draws the whole workspace, in place of **Canvas** or **Windows**.
- **Tiles** inside it: an **agent tile** started from an agent file, a **terminal**, and a **tool tile** drawn by a tool.
- Each tile is lent to the view. Switching views keeps it running.
- **Widget**: a small card that floats above every view.

## The four kinds

| Kind | What it adds | Its file |
|---|---|---|
| **Agent** | a coding agent's own program, which Hivemind starts and reads | `agent.yaml` |
| **View** | a way of drawing the whole workspace | `hivemind-view.json` |
| **Widget** | a small live card on the <Tooltip tip="The view that lays your frames, tiles and widgets out on one endless surface." cta="Glossary" href="/glossary#canvas">canvas</Tooltip>, in every view | `widget.json` |
| **Tool** | a new kind of tile | `hivemind-tool.json` |

## Add one

Install one from **Settings → Plugins**, on the **HiveHub** tab. What HiveHub lists, how each file
is checked, and what you review first: [What HiveHub is](/hivehub).

From a terminal:

```bash
hive plugins list                            # every plugin here, on or off
hive plugins install @dip497/worktrees        # a tool, widget or view, from HiveHub or a folder
hive plugins enable @dip497/worktrees         # a tool arrives switched off
hive plugins set @you/board columns all      # a setting the plugin declares
hive agents install claude                   # agents have their own command
```

Each plugin's page in **Settings → Plugins** has **Settings**, **Read me** and **What it can do**.

## Packages

Everything you install is a package, and goes in and out as one. A folder that holds one plugin
is a package of one. Removing a plugin you installed removes its package. What you set a plugin
to stays in your settings, so installing it again finds it.

A package's files are copied in and checked before anything you use changes. If an install
fails halfway, the version you had stays in use.

A package that holds several is a folder with a `hivemind-package.json`. It names a folder for
each tool, widget, view and [theme](/packages#themes), each with its own manifest, and the agent
presets it brings:

```json
{
  "apiVersion": 2,
  "id": "@you/kit",
  "name": "Kit",
  "version": "1.0.0",
  "tools": [{ "path": "tools/prs" }],
  "widgets": [{ "path": "widgets/dog" }],
  "views": [{ "path": "views/island" }],
  "themes": [{ "path": "themes/harbour" }],
  "agents": [{ "id": "@you/reviewer", "name": "Reviewer", "provider": "claude", "prompt": "Review the diff." }]
}
```

Every member's id has the package's owner (`@you/…`). Installing checks each member as its kind
is checked, and refuses one whose id another installed package holds.

In **Settings → Plugins**, the **Packages** tab lists each package that holds several plugins as
one row with one switch. Open it to see its members: what kind each is, whether it is sandboxed or
runs in the app, its own switch, and its own page for its settings. Each member is also listed in
its kind's tab, marked **Part of** its package. To add one from your computer, choose
**Add → Add from a folder**; the review shows what it holds before anything is installed.

A plugin that is part of a package changes only with it. Installing it, removing it or switching
it on apart from its package is refused, naming the package. You can switch one off on its own,
and on again while its package is on. A plugin you installed on its own before is taken over
only by a package that lists it in `"replaces": ["@you/name"]`; what you set it to is kept. `hive plugins list` shows which package each
plugin belongs to.

A package published on HiveHub installs by its id, like a single plugin. Its HiveHub page and
the review in **Settings → Plugins** list each member, whether its code is sandboxed or runs in
the app, and what it asks for.

### Updates and rollback

Views and widgets run in a sandbox that holds them to the permissions they ask for. A theme is
data, with no code. Tools run in the app, and an agent preset is instructions an agent follows. So
a new package that holds a tool or an agent preset arrives switched off, and one of only views,
widgets and themes arrives on.

Installing a newer version of a package keeps its switch, unless something in it needs you to
trust it again: a view or widget that asks for a permission it did not have, or a tool or agent
preset that is new or changed. Then the package goes off until you switch it on.

```bash
hive plugins install ./kit --dry-run   # what would change, member by member; installs nothing
hive plugins install ./kit             # the update, with the same list of changes
hive plugins rollback @you/kit          # back to the version before, on or off as it was
```

In the app, the same review lists what changed in each member and why the package will switch
off, and an opened package has **Roll back to** the version before.

The version before the one in use is kept, so a rollback needs no download. Rolling back again
returns to the newer one.

## Make one

To make your own, use **Add → Make your own…** in the toolbar, or **Add → Make your own** in
**Settings → Plugins**. Both write a prompt you hand to a coding agent.

From a terminal, start one of any kind:

```bash
hive plugins new widget my-widget    # or: tool, view
```

Each starter includes `PROMPT.md`: the whole contract for that kind in one file. Write what you
want at the top, then hand the file to a coding agent.

## Agents can run a plugin's commands

A view, widget or tool can declare `"commands"` in its file and answer them in its code. An agent
lists and runs them while the plugin is open:

```bash
hive ctl plugin commands
hive ctl plugin call @dip497/worktrees list
```
