Your agents build the workspace they work in. They start other agents, open views, add widgets
and run tools with the same `hive` command you use. This page shows the parts behind that, and
where each one runs.

<Diagram name="architecture" caption="What runs where" />

- **Desktop app**, on your computer: the windows, the canvas and views. It starts the background process and hive-net.
- **Background process**, on your computer: runs every terminal and agent, and works out each agent's state. It talks to the app over a local socket.
- **Your agents** run in terminals of the background process. Their hooks tell it what they do.
- **hive command**: you, your agents and your programs drive the app through `drive.sock`.
- Desktop app → **HiveHub**: https, to install plugins.
- Desktop app → **network server**: encrypted end to end. Your server relays it, and serves the **phone page** over https.
- Desktop app → **machine**: ssh. Network server ↔ **host**: relay.
- Stays on this computer: your keys, settings, API tokens and saved screens.

## For agents

Everything an agent does goes through `hive ctl` on the drive socket, or the same methods from
your own program with a token ([API](/api)). Which part each one touches:

| Part | `hive ctl` | API methods |
|---|---|---|
| Agents in the background process | `agents`, `spawn`, `send`, `keys`, `read`, `stream`, `sessions`, `sleep`, `wake`, `rename`, `close` | `agent.*`, `status.all`, `terminal.*` |
| Agents working together | `workflow`, `approve`, `approval`, `report`, `inbox`, `connect`, `disconnect` | `link.connect`, `link.disconnect` |
| Workspace and frames | `frames`, `frame add`, `list-workspaces` | `frame.open`, `frame.close`, `worktree.list`, `store.*` |
| Desktop app windows | `focus`, `open-review` | `presence.set`, `appearance.get` |
| Plugins | `plugin list`, `plugin open`, `plugin commands`, `plugin call`, `plugin close`, `open-tool`, `view emit` | `widget.*`, `tool.open`, `view.*` |
| Issues | `set-state`, `add-comment`, `mark-acceptance`, `delete-issue` | `issue.list`, `issue.read` |
| hive-net, phone, machines, hosts | none: use `hive network`, `hive machine`, `hive host` | none |

`hive ctl` needs the app or `hive host` running for the workspace; it exits 3 when neither is.
Every command is in the [CLI reference](/cli), every method in [Methods](/api-methods).
