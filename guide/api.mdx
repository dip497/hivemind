The API lets a program on your computer drive a <Tooltip tip="One project folder and everything open for it." cta="Glossary" href="/glossary#workspace">workspace</Tooltip> the way you do. Think of an orchestrator that hands work to agents, a dashboard of who is waiting, or a script your CI calls.

## How it works

Your program talks to the app through a local connection that only your user can open (`drive.sock`, a named pipe on Windows). The app serves it, or `hive host` when that runs instead.

| Piece | What it is |
|---|---|
| **Token** | A secret your program sends first. You make it in **Settings → API access** or with `hive grant create`. It is shown once. |
| **Role** | What the token may do: `view`, `edit`, `terminals` or `agents`. These are the same roles people get when you [share a workspace](/multiplayer). |
| **Messages** | One line of JSON per message, both ways. You send calls; the app sends answers and events. |

## Why it works this way

A token reaches only the workspaces you name, at one role. A call the role does not allow is refused before it runs. Revoking a token closes its connections at once. So a program never does more than you chose, and never for longer than you allow.

Whatever its role, a program cannot share the workspace, let people in, change their roles, or make or revoke tokens. Those stay with you.

<Warning>
The `terminals` and `agents` roles can still change files and run any command, `git push` included. They do it through a shell they type into, or an agent they start.
</Warning>

## Without writing a client

`hive ctl` speaks the same API. To act as the program, give it the token:

```bash
export HIVE_DRIVE_TOKEN=hgr_…
export HIVE_WORKSPACE=~/work/api      # only when the token reaches several workspaces
hive ctl agents --json
hive ctl spawn --agent claude --prompt "Run the tests"   # needs the agents role
```

A [tool's service](/tool-plugins#a-service-that-keeps-running) gets its own token this way. It is made when the service starts and revoked when it stops.
