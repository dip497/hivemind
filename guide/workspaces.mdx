A <Tooltip tip="One project folder and everything open for it." cta="Glossary" href="/glossary#workspace">workspace</Tooltip>
is one project folder and everything open for it. Inside it, frames group tiles by folder, and
every tile in a frame runs in that folder.

## How it works

| Word | What it is |
|---|---|
| **Workspace** | one project folder and everything open for it |
| **<Tooltip tip="A named area bound to one folder: the project, a git worktree, or a folder on another computer. Every tile in it starts in that folder." cta="Glossary" href="/glossary#frame">Frame</Tooltip>** | a named area bound to one folder |
| **<Tooltip tip="One thing in a frame: an agent, a terminal, the Code tile, a browser or a tool." cta="Glossary" href="/glossary#tile">Tile</Tooltip>** | one thing in a frame: an agent, a terminal, the Code tile, a browser or a tool |

A frame can be bound to three kinds of folder:

| A frame on | Tiles run | How to make one |
|---|---|---|
| the project folder | in that folder | the default |
| a git worktree | in the worktree, on its branch, nested under the project | [Work in a git worktree](/git-worktree) |
| a folder on another computer | on that computer, over ssh | [Run agents on another computer](/machines) |

A frame's ⋯ menu also arranges its tiles (**Arrange**), starts an agent in it, and adds a tool or
widget. Deleting a frame that holds tiles asks whether to **Keep them** or close them with it.

### The Layers panel

The <Tooltip tip="The list beside the canvas of your projects, frames and tiles. ⌘B / Ctrl+B shows or hides it." cta="Glossary" href="/glossary#layers-panel">Layers panel</Tooltip>
lists everything open. Its rail picks what it shows:

| Pane | Lists |
|---|---|
| **Tiles** | **Pinned**, then each project with its worktrees and tiles. Agents a tile started fold under it. |
| **Recents** | past agent sessions, newest first. One click resumes one. |
| **Machines** | this computer and every machine you added, with how many agents there need you. |

Its title menu switches workspace, opens a folder, joins a shared workspace and switches views.
Its bell jumps to the next agent that needs you. A row's ⋮ menu pins, renames, closes, snoozes
or puts an agent to sleep. Its keys are on [Keyboard shortcuts](/keyboard-shortcuts).

The **View** menu over the tiles filters, groups and sorts them. Your pins, snoozes and what you
have read are yours alone, on this computer, even in a shared workspace.

### What is kept

| When | What happens |
|---|---|
| You close the window | Terminals and agents keep running in a background process. |
| That process restarts, or the computer reboots | Agents that can resume continue their conversation; others start fresh. Screens replay from disk. |
| You close a tile (×) | Its program ends. |
| You put an agent to sleep | Its program ends. Its tile keeps its name and conversation, with **Resume**. |

Frames, tile positions, the viewport and open files are saved per project, on this computer. They
are not written into the repository.

## Why it works this way

A frame binds a folder so that a tile never asks where to start. An agent started in a worktree's
frame edits that branch only. One started in a machine's frame runs on that machine. You choose
the place once, on the frame, and every tile follows it.
