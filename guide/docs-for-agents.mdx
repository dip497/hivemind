## Connect the docs MCP server

These docs run their own MCP server. Your agent uses it to search the docs when it needs to.

<DocsMcpCommands />

The page menu at the top of every page also has **Connect to MCP**, and buttons that add the
server to Cursor or VS Code in one click.

**Check:** ask your agent "How do I install Hivemind?" It answers with the install command from these docs.

## Teach it Hivemind with the hive skills

To let an agent work in Hivemind on its own, add the hive skills to your project.

```bash
cd ~/my-project && hive add skill
```

**Check:** `.claude/skills/` now holds `hive-work`, `hive-workflow`, `hivemind` and
`hive-browser`. An agent that reads skills learns to pick up issues and to start and coordinate
other agents with `hive ctl`.

## Use the prompt on each page

A page that describes something you set up or do starts with a prompt. Paste it into Claude Code,
Codex or any coding agent, and it does the job on your computer. Each prompt says what to check at
the end. It asks you for anything only you can do, such as a password, a sudo or a DNS record.
Each one ends with a `REFERENCE` line: the page as Markdown, for the agent to read.

## Rules for agents that read these docs

- Prefer `hive ctl … --json`, and check `hive <command> --help` before using a flag.
- Never ask a person for a token's value. Tell them to make one in **Settings → API access**.
- Use the smallest role that does the job.
- Ask the person before installing anything, and never type a password.
