Run agents on a bigger or always-on computer while you watch them from your own. You reach it with `ssh`.

How a machine runs your agents, and how it differs from a host: [Machines and hosts](/remote-machines).

## Before you start

- The computer runs Linux, macOS or Windows, on x86_64 or arm64, with an ssh server you can log in to. On Windows that is **OpenSSH Server**, under **Settings ▸ System ▸ Optional features**.
- You answered its host-key question once, in a terminal: `ssh user@host`.
- The agent programs you want to run there are installed on it.

Hivemind uses your own OpenSSH: your keys, your ssh agent and `~/.ssh/config`. A password, if you use one, goes in the system keychain.

## Add the machine

<Tabs>
  <Tab title="In the app">
    1. Open the <Tooltip tip="The list beside the canvas of your projects, frames and tiles." cta="Glossary" href="/glossary#layers-panel">Layers panel</Tooltip> (⌘B / Ctrl+B) and choose **Machines**.
    2. Press **New machine**.
    3. Fill in **Host** (`user@host` or an ssh alias) and **Name**.
    4. Leave **Install hive there** off, or turn it on to [keep terminals running](#keep-terminals-running).
    5. Press **Add**.

    Check: the machine shows in the **Machines** pane, not grey.
  </Tab>
  <Tab title="In a terminal">
    1. Add it. `--install-hive` puts this version's `hive` there, to [keep terminals running](#keep-terminals-running):

       ```bash
       hive machine add dev@build-box --label build --install-hive
       ```

    2. Check it:

       ```bash
       hive machine check build
       ```

       It prints a line like `build: reachable, linux-x86_64, hive 2026.10.6 at /home/dev/.hivemind/bin/2026.10.6/hive`, or `terminals over plain ssh` without `hive`.
  </Tab>
</Tabs>

## Open a folder on it

<Tabs>
  <Tab title="In the app">
    1. In the **Machines** pane, press **+** on the machine, or ⋯ → **Open folder here…**.
    2. Pick a folder. On Windows the drives come first.

    Check: it opens as a new <Tooltip tip="A named area bound to one folder: the project, a git worktree, or a folder on another computer." cta="Glossary" href="/glossary#frame">frame</Tooltip>. Terminals, agents and the Code tile in it all run on the machine.
  </Tab>
  <Tab title="In a terminal">
    ```bash
    hive ctl frame add --machine build --folder /srv/web --name web
    hive ctl spawn --frame web --agent claude --prompt "Run the tests and fix what fails"
    ```

    On Windows, give the folder as `--folder 'C:\work\web'`.
  </Tab>
</Tabs>

## Check it worked

Run `pwd` in a terminal in the new frame. It prints the folder on the machine.

## Keep terminals running

A new machine runs each terminal as a plain ssh session. It ends when the network drops, your
laptop sleeps or the app quits.

With **Install hive there** on, the app copies its own `hive` (about 120 MB) to the machine.
Terminals and agents then keep running there through all of that and reattach when you are back,
and agents there can be put to sleep. Turn it on later with the **Terminals** switch in
**Manage machines…**, or:

```bash
hive machine install-hive build          # --off: new terminals run over plain ssh again
```

Windows machines run over plain ssh only for now: `hive` is not put on them.

With `hive` there, you reach its terminals without the app too:

```bash
hive ps --machine build
hive attach <session> --machine build     # ctrl-b d detaches
hive run --machine build --cwd /srv/web -- npm test
hive kill <session> --machine build
```

Hivemind keeps that `hive` up to date itself, one copy per version in `~/.hivemind/bin/`. When
you update the app, it puts its new version there the next time it connects, and keeps the two
before it.

## Several people on one login

People who log in to a machine as the same user each get their own terminals there, in
`~/.hivemind/people/<person>/`. One person's update never stops another's agents. They are kept
apart, not hidden: anyone on that login can still open the other folders. For privacy, give each
person a login of their own.

## Manage it

A machine's ⋯ menu in the **Machines** pane has:

| Item | Does |
|---|---|
| **Check now** | Connects again and checks it. |
| **Pause** | Stops connecting. Nothing on the machine stops. **Resume** connects again. |
| **Manage machines…** | Edit it, set its password, or **Remove…** it. |

To be told when an agent there needs you, even with your laptop closed, run this on the machine:

```bash
hive push set https://ntfy.sh/your-topic
hive push test
```

## If it didn't

| You see | Do |
|---|---|
| The machine is grey | It is paused or unreachable. Press **Check now**. |
| **Sign in** on the machine | It asks for a password. Give it once, or set up an ssh key. |
| **hive could not be put there** | The machine has no `curl` or `wget`, or its disk is full. Fix that and press **Check now**; until then its terminals end when the connection drops. |
| `unsupported remote platform` | The computer is not Linux, macOS or Windows on x86_64 or arm64. |

More in [Troubleshooting](/troubleshooting).

## Good to know

- Issues are read from your own computer, not from the machine's folder.
