Point at what should change, in an agent's diff or on a web page, and the agent fixes it as its next task.

<AgentPrompt description="Paste this into your coding agent so it answers the review comments left on its work." page="review">{`

2. For each comment, read it with \`hive review show <id>\` and run \`hive review seen <id>\`. A comment on a diff names a file and line. A note on a page names the page, each element it points at with a CSS selector, and a picture file to open. Make the fix.
3. Run the project's tests or build to check the fix.
4. Reply with what you changed: \`hive review reply <id> "<what changed>"\`. Then run \`hive review resolve <id> --summary "<how it was fixed>"\`.
5. If you disagree with a comment or cannot do it, run \`hive review dismiss <id> --reason "<why>"\`. If it is a question, answer with \`hive review reply <id> "<answer>"\`.

## Comment on an agent's changes

1. Select the agent's frame and press **3** to open the Code tile.
2. Switch the Code tile to **Changes**.
3. Check: each changed file shows its diff, and it updates as the agent edits.
4. Select a line and leave a comment.
5. To send it, press **Send review to Claude** for every comment, or **→ claude** on one.
   Then pick the agent in **Send to agent**.
6. Check: the agent receives it as its next task, starting *Address this review comment*.

Comments are kept in `.hivemind/review.json`, so an agent can also read them itself. These
commands work with or without the app:

```bash
hive review list --status open
hive review show <id>
hive review reply <id> "fixed in 3f2c1a"
hive review seen <id>                # you are on it
hive review resolve <id> --summary "how it was fixed"
hive review dismiss <id> --reason "why not"
hive review reopen <id>
hive review watch --timeout 300     # wait for the next comment
```

## Leave notes on a web page

1. In a Browser tile, open the page and press the notes button in its toolbar.
2. Check: the pointer outlines what it is on.
3. Click something to note it. Hold Ctrl (⌘ on a Mac) and click to gather several, then click
   one more. Drag to note an area.
4. Write what should change, pick **Fix**, **Change** or **Question**, and press Enter.
5. Check: a numbered pin shows on the page, and the note is in the list under the address bar.
6. Press **Send to an agent** and pick the agent.
7. Check: the agent receives the open notes, with a picture of each and how to answer them.

As the agent works, each pin shows where its note stands: blue is open, orange is seen, a check
is done, and grey is dismissed. **Hold still** stops the page's animations and videos, so a moving
thing can be clicked. Notes work the same from another computer, in the app served to a browser:
see [Use the app in a browser tab](/browser-tab).

On your phone, open an agent and choose ⋯ ▸ **Notes on pages**. It lists the notes in that agent's
workspace. **Send** gives the open ones to that agent, and each note can be marked **Done**,
**Dismiss**ed with a reason, or **Reopen**ed.

Notes are review comments, kept with the diff's in `.hivemind/review.json`. An agent answers them
with `hive ctl notes`:

```bash
hive ctl notes list
hive ctl notes seen <id>
hive ctl notes done <id> --summary "what was done" --attach fixed.webm
hive ctl notes dismiss <id> --reason "why not"
```

`--attach` keeps a video or image on the note as proof (`.webm`, `.mp4`, `.png`, `.jpg` or `.gif`,
up to 200 MB each; repeat it for several). The note's list plays or shows it, and
`hive ctl notes show <id>` prints where it is. The phone says how many there are and their names;
it does not play them.

### Notes an agent leaves

An agent that finds a problem on a page leaves a note the same way, on the Browser tile in its
frame:

```bash
hive ctl notes add --selector "#checkout" --body "this button does nothing" --intent fix --attach broken.webm
hive ctl notes add --area 0,400,800,300 --body "this part is cut off"
```

Check: a pin with square corners and a star shows on the page, and the list names the agent. These
notes go out with yours when you press **Send to an agent**. Deleting a note deletes its picture
and what is attached to it.

A selector that finds nothing or several elements, or no Browser tile in the frame, is refused
with what to do next. `--tile` names a Browser tile, and `--area` is in page pixels.

## Approve an agent's plan

An agent can ask you to approve a plan before it starts the work.

1. The agent runs `hive ctl open-review --file plan.md`.
2. Check: a **Plan review** tile opens beside the agent, and the agent waits.
3. To ask for changes, select text in the plan or hover a block, and comment. Then press
   **Request changes**.
4. To go ahead, press **Approve plan**.
5. Check: the agent's `open-review` command prints your decision, and the agent carries on.

The agent waits up to 24 hours unless it passes `--timeout`.

## If it didn't

| You see | Do |
|---|---|
| **3** does nothing | The frame has no project folder. Select a frame bound to a folder. |
| The agent never gets your comment | Send it again and pick that agent in **Send to agent**. |
| `hive review watch` exits 4 | No comment came in time. Run it again, or with a longer `--timeout`. |
