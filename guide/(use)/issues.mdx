Write down the work, then let agents pick it up. Each <Tooltip tip="A piece of work written as a Markdown file in .hivemind/, which you and your agents read and update." cta="Glossary" href="/glossary#issue">issue</Tooltip>
is a Markdown file in the project, so the Issues board updates as an agent works.

5. Check: \`hive list --json\` lists them, with ids <PREFIX>-1, <PREFIX>-2 and so on.

## Turn issues on

<Tabs>
  <Tab title="In the app">
    1. Press **Add**, choose the **Tools** tab, then **Issues**.
    2. Type an **Issue prefix**, such as `MYP`, and press **Set up issues**.
    3. Check: the Issues tile shows an empty board.
  </Tab>
  <Tab title="In a terminal">
    1. In the project folder, run `hive init --prefix MYP`.
    2. Check: a `.hivemind/` folder now exists.

    `hive init` also adds agent skills and a section in `CLAUDE.md`. For the issues alone, add
    `--no-agentic`.
  </Tab>
</Tabs>

The prefix is 2 to 10 capital letters or digits, starting with a letter. Issue ids are `MYP-1`,
`MYP-2`, and so on.

## File an issue

To file one, run `hive new` with a title. `--ac` adds acceptance criteria, the checks that say the
work is done. `||` separates them:

```bash
hive new "Fix token expiry" --ac "boundary test passes || manual check passes"
```

Check: `hive list --state todo` or the board shows it. Other everyday commands:

```bash
hive show MYP-1
hive update MYP-1 --assignee claude --assignee-type agent
hive close MYP-1                  # done; --reason "…" makes it cancelled
hive reopen MYP-1                 # back to todo
```

## Hand an issue to an agent

1. On the Issues board, press **work** on a card. In an open issue, press **Work on this**.
2. Check: an agent's tile opens with the issue as its task, ready for you to send.
3. Send it. The agent follows the steps below and ticks each criterion on the board.

An agent started with `hive init`'s skills follows these steps:

<Steps>
  <Step title="Read">
    `hive show MYP-42 --json`: the issue and its acceptance criteria.
  </Step>
  <Step title="Claim">
    `hive ctl set-state MYP-42 in_progress`, and it assigns itself.
  </Step>
  <Step title="Plan">
    `hive ctl add-comment MYP-42 "plan: …"`.
  </Step>
  <Step title="Work">
    After each criterion, `hive ctl mark-acceptance MYP-42 <n>`, counting from 0.
  </Step>
  <Step title="Check">
    It runs the tests and build, and commits with the issue id.
  </Step>
  <Step title="Hand back">
    It ends every session with `hive ctl set-state`: `in_review`, `done`, `in_progress --note`,
    or `cancelled --note`.
  </Step>
</Steps>

`.hivemind/.agent.md` sums up the open issues, so a new agent session reads one file.
`hive agent context` writes it again.

## Move an issue through its states

<Diagram name="workspaces-issue-states" caption="The usual track; nothing enforces it" />

- Usual order: `backlog` → `todo` → `in_progress` → `in_review` → `done`.
- `cancelled` can be set from any state, and any state can be set from any other: the order is not enforced.
- `hive close` sets `done`, `hive close --reason` sets `cancelled`, and `hive reopen` sets `todo`.

Every change is a line in the issue's activity, signed by the person or agent who made it.

## Split and link issues

```bash
hive task MYP-3 add "Write the test"     # MYP-3.1
hive new "…" --parent MYP-3
hive relate MYP-3 OPS-7 --type blocks    # written on both issues
hive move MYP-3 OPS                      # to another project; --copy keeps the original
```

Link types are `relates`, `blocks`, `blocked-by`, `duplicates`, `parent-of` and `child-of`. To use
ids from another project, run `hive workspace register` in both, then `hive workspace list`.

## What is in the folder

```text
.hivemind/
├── issues/MYP-1.md   one file per issue (sub-issues in issues/MYP-1/)
├── config.yaml       prefix and next id
├── review.json       comments left on a diff
└── .agent.md         a summary of open issues for agents (not committed)
```

## If it didn't

| You see | Do |
|---|---|
| `no .hivemind/ found in this directory or any parent` | Run `hive init --prefix <PREFIX>` in the project folder first. |
| The prefix is refused | Use 2 to 10 capital letters or digits, starting with a letter. |
| The board does not show a new issue | Check it was filed in the same project folder. |
