A tool plugin adds a kind of tile. It sits on the board beside terminals and the Code tile, in
every view. The Browser, Issues and the Code tile are tools that come with the app.

<Prompt description="Paste this into your coding agent to build a tool plugin (a new kind of tile), try it in Hivemind and publish it." actions={["copy","cursor"]}>
Build a Hivemind tool plugin, a new kind of tile drawn by React code inside the app, then publish it on HiveHub.

1. Ask me what the tile should show and do, and its name (lowercase letters, digits and dashes).
2. Start it: `hive tools new` with that name. It takes the owner from the GitHub account `gh` is signed in as; if `gh` is not signed in, ask me for my GitHub login and pass `--owner`. The folder has `hivemind-tool.json`, `index.js`, `README.md` and `PROMPT.md`.

4. Install and switch it on, again after each change: `hive tools install .` then `hive plugins enable tool:owner/name` (once). Open it with `hive ctl plugin open tool:owner/name`.
5. Give it at least one command in the manifest's `"commands"`, answered with `hm.onCommand`, that reports what the tile shows. Use `hive ctl plugin call owner/name` with that command to check it works.
6. Done means: `hive plugins list` shows it on with no problem; it reads well in the light and the dark theme; the manifest has a one-line description, a `category` and only the permissions it uses; `README.md` says what it does and what it asks for.

At the end, tell me the tool's id, the command that installs it (`hive tools install owner/name`), and anything you could not check.

A tool runs inside the app with your access: your files, programs and logins. So one you add is
switched off until you turn it on, on its page in **Settings ▸ Plugins** or with
`hive plugins enable tool:<owner>/<name>`. If one breaks the app, start it with
`HIVEMIND_SAFE_MODE=1 hivemind`.

## Make one

```bash
hive tools new my-tool
cd my-tool && hive tools install . && hive plugins enable tool:<you>/my-tool
```

A tool is a folder with `hivemind-tool.json` and an ES module:

```json hivemind-tool.json
{
  "id": "acme/prs",
  "name": "Pull requests",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "One line, shown in Settings.",
  "category": "git",
  "entry": "index.js",
  "permissions": ["workspace:spawn"],
  "settings": [
    { "id": "state", "label": "Show", "type": "choice", "values": ["open", "all"], "default": "open" }
  ],
  "tools": [
    {
      "key": "prs", "label": "Pull requests", "description": "What its tile shows.",
      "tileKind": "acme-prs", "size": { "width": 1100, "height": 760 },
      "needsRepo": true, "singleton": true, "glyph": "⇅", "icon": "icon.svg"
    }
  ]
}
```

| Field | Means |
|---|---|
| `id` | `owner/name`; `hivemind/` is kept for the app's own |
| `tools[]` | one entry per kind of tile; `needsRepo` hides it in a frame with no repository, `singleton` focuses the open one instead of opening another |
| `icon` | an `.svg` in the folder (32 KB at most); without one, `glyph` is shown |
| `permissions`, `settings` | the same as a view's ([Write a view](/extension-authoring#permissions)) |

The module's default export says which component draws each tile kind:

```js index.js
import React, { useEffect, useState } from "hm-plugin://host/react.js";
import { Button, PatchView } from "hm-plugin://host/sdk.js";

const h = React.createElement;

function PullRequests({ tile, hm, host }) {
  const [list, setList] = useState([]);
  useEffect(() => {
    host.run("gh", ["pr", "list", "--json", "number,title"], { maxAgeMs: 30_000 })
      .then((r) => setList(JSON.parse(r.stdout)));
  }, [host]);
  return h("ul", null, list.map((p) => h("li", { key: p.number }, `#${p.number} ${p.title}`)));
}

export default { tiles: { "acme-prs": PullRequests } };
```

It imports the app's own React and parts from `hm-plugin://host/` (`react.js`,
`react-jsx-runtime.js`, `sdk.js`, `ui.js`), so it bundles none of them.

## What a tile gets

| Prop | What it is |
|---|---|
| `tile` | `{ id, kind, name, frameId }` |
| `hm` | the client a view has (`@hivemind/view-sdk`): the workspace's frames, tiles and names, agents' status and events, commands (`hm.commands.spawnAgent`, `focusTile`…), requests (`hm.prompt`, `hm.agents()`), its settings (`hm.settings`, `hm.on("settings")`) and its saved state, kept per tile (`hm.hello.layout`, `hm.setLayout`). Each is held to the permissions the manifest declares. |
| `host` | what only a tile has: `repoPath`, `cwd`, `run(bin, args, { maxAgeMs, stdin })` (a program on PATH, in the tile's folder, without a shell), `openFile(path)` in the frame's Code tile, `openUrl(url)` in the frame's browser |
| `selected` | it has the person's focus |

`sdk.js` has `Button`, `PatchView` (a diff), `Markdown`, `Loading` and `useTileState(hm, key, initial)`,
which keeps a value with the tile across restarts. `ui.js` is the app's whole UI kit (`Button`,
`Input`, `Dialog…`, `DropdownMenu…`, `Switch`, `toast`, …). The built-in Issues tile
(`apps/desktop/tools/issues`) is the fullest example.

Reach the app only through these, never `window.hive`.

## Commands agents can run

Declare them in `hivemind-tool.json`, answer them in the tile:

```json
"commands": [{ "name": "list", "description": "Every worktree, with its branch and what is not committed." }]
```

```js
useEffect(() => hm.onCommand("list", () => trees), [hm, trees]);
```

`hive ctl plugin call dip497/worktrees list` prints what the handler returns. It works while a
tile of the tool is open; with two open, name one with `--tile`.

## A service that keeps running

A tool can bring a program the app keeps running while the tool is on: an orchestrator, a
dashboard, a watcher. It drives workspaces through the [API](/api), with its own token.

```json
"service": { "command": ["node", "service.js"], "role": "agents" }
```

`role` is one of the [API roles](/api-tokens#roles). Once switched on, it waits until you pick
the workspaces it may drive, on its page (or `hive plugins workspaces tool:<id> <folder>` where
`hive host` runs it). It is then started with:

| Variable | What it holds |
|---|---|
| `HIVE_DRIVE_SOCK` | the drive socket, where it connects |
| `HIVE_DRIVE_TOKEN` | its token: the first line it sends is `{"hello": {"token": …, "workspace": …}}` |
| `HIVE_WORKSPACES` | the folders it may drive, separated as in `PATH` |

It is restarted after a crash (1 s, then 2, 4… up to a minute), and stays stopped after a clean exit
or when its token is revoked. It should exit when its stdin closes. Its output is on its page.

## On a shared board

A guest sees a tool's tile if they have the same plugin switched on. A tile's programs run on the
machine of the person looking at it.
