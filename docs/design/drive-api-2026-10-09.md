# One API to drive a workspace (2026-10-09)

Status: accepted 2026-10-09. Asked for by issues #84–#88 (an outside orchestrator driving
hivemind). Finishes R8 step 5 of `multiplayer-2026-09-28.md`.

## Goal

Every client that drives a workspace (a window, the phone, a peer, `hive ctl`, an outside
program) sees the same agents, frames and waits and acts on them through one API, as an identity
with only the rights it was given.

**Done when:** a client holding a scoped grant, not the install token, opens a frame on a new
worktree, starts Claude there, sees it wait on Claude's folder-trust screen by name, reads its
session and conversation, answers a supervised approval it is the supervisor of, and is refused
`git.push`; and HCP's method list is a fixed allowlist a test holds.

## Dropped

| Choice | Why it no longer holds |
|---|---|
| Outside programs use HCP | Two front doors: each feature built twice, the specs already disagree in three places |
| The local socket waits for hive-net | Its reason was "no caller"; there is one |
| The install token is the only identity a program can hold | A program driven by a model can be talked into `people.invite`; it gets a scoped grant |
| Each kind of wait keeps its own store and answer | Every new kind repeats it (#86 is the fourth) |
| Frames are the window's | Nothing creates one without a window (#84) |
| A parent or supervisor is a tile | An outside program supervises the agents it starts |

Decided with the drops: a grant names one or more workspaces explicitly, never "all"; agents'
tile tokens keep what they may do today (a separate decision).

## Design

```
window ─IPC────────────────────────────┐
phone / peer ─hive-net─────────────────┤
hive ctl, programs ─drive socket─────────┼─► workspace API ─► intents + audit ─► store · status · waits · frames
agent hooks ─hcp.sock (tile token)─► agent channel: event · await_approval · reply · report · title · screen
```

- **The drive socket** (`drive.sock` beside `hcp.sock`, 0600; a named pipe on Windows) carries
  the workspace API's stream frames (`{id, method, params}`, events, notices). Its first line is
  `{hello: {token, workspace?}}`. The install token is the person: a connection like a window's,
  every workspace and the machine's own methods. A grant's token is a **client**: one workspace
  per connection, served by `servePeer` with the grant's role.
- **A grant** is `{id, name, workspaces, role, createdAt, expires}`, its token kept only as a
  hash, listed and revoked in Settings, every effect audited under it. `hive grant` makes one.
- **The workspace's place** is its repo and its frames' worktrees, for every scoped caller
  (a client or a guest).
- **Frames** are the store's: `frame.open {path} | {worktree: {repo, branch, base?}}`, idempotent
  by real path, and `frame.close {frame, removeWorktree?}`; the window lays a frame out when it
  hears `frame.opened`.
- **Waits**: one record, `{tile, since, kind, says?, plan?, tool?, summary?, expiresAt?}`, made by
  plans, supervised approvals, permission and question screens and named startup screens; listed
  in `agent.list`, told by `agent.event`, answered by `agent.answer`.
- **A parent** is a tile or a client connection: a worker's reports and approvals go to whichever
  started it.

## Steps

Each lands with its spec, CHANGELOG line, tests that fail without it, and this plan's row.

1. Drive socket and grants: the person's connection and `servePeer` for a client; `hive grant`;
   Settings lists and revokes. Check: a client with role `agents` starts an agent, is refused
   `git.push`, hears nothing of another workspace.
2. A workspace's place includes its worktrees; frames in the store; `frame.open`, `frame.close`.
3. `agent.start` parity and a client as parent.
4. One waits model; the approval map and `review.open`'s path go.
5. Detect rules may say what a screen is (`says`); Claude's trust, bypass and settings screens.
6. Session id and transcript in `agent.list`; `agent.changed` on a new session.
7. `hive ctl` on the drive socket; HCP keeps the agent channel alone (**Breaking:** for programs
   calling HCP's other methods).
   - 7a. An agent's tile on the drive socket: its token is a client of its own workspace, role
     `agents`, the parent of what it starts and the supervisor it names. One `parent` for a spawn
     (a tile or `client:<grant id>`); depth is counted from a tile parent, as `callerTile` was.
   - 7b. What HCP answers and the API does not: `agent.rename`, `agent.keys`, `agent.read`,
     `agent.sessions`, `tool.open`, `link.connect`/`link.disconnect` (each with its least role);
     the person's machine methods (`view.emit`, `plugin.*`, `tile.focus`, the rescans,
     `settings.reload`, `host.status`, `host.join`), the person's alone.
   - 7c. `hive ctl` speaks the drive socket, events too (`agents --watch`, `stream`). (Planned: a
     remote machine's daemon passing `drive.sock` on as it passes `hcp.sock` on. Not needed: `hive
     host` serves `drive.sock` in the folder its agents are told, and with no host there is nothing
     to answer a drive call, where a hook needs the daemon's answer.)
   - 7d. HCP's methods are the agent channel's, held by a test; `spec/wire-protocol.md`, the pi
     fixture and the docs follow.
8. Services in tool plugins, each given a grant when the plugin is switched on.

Known ceiling: 16 spawns a minute for everyone (1,000 spawns: about an hour).
