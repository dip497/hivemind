# API SDKs for TypeScript and Python (2026-10-18)

A program drives a workspace through the drive socket with a token (`spec/workspace-api.md`,
"Drive socket"). Until now it hand-wrote the protocol: the hello, ids, answers out of order, events
that come as a list. Two SDKs do it, with the same shape.

```
  a program (TypeScript)        a program (Python)           hive ctl / grant / …
          │                             │                            │
          ▼                             ▼                            ▼
  packages/sdk                  packages/sdk-python            apps/cli/src/drive.ts
  "hivemind-api" (.tgz)         "hivemind_api" (.whl)          (the CLI's exit codes)
   client.ts   the jobs          client.py / aio.py  the jobs          │
   connection.ts  the wire       calls.py   each job's call            │
   places.ts   the defaults      connection.py  the wire (asyncio)     │
          │                      places.py  the defaults               │
          │◄─────────────────────────────────────────────── uses ──────┘
          │                             │
          └──────────── drive.sock (lines of JSON; a named pipe on Windows) ───────────┐
                                                                                         ▼
                                                               the app or `hive host`
                                                               (packages/host/src/drive.ts)

  conformance/drive.json ── played by a fake host over a real socket ──► both SDKs' runners
```

## One owner per job

- **Where the app keeps its data** is `@hivemind/core/app-data` (moved from the CLI), beside
  `ipcPath`, which names the sockets in it. The CLI and the TypeScript SDK both read it.
- **The defaults a program connects with** (`HIVE_DRIVE_SOCK`, `HCP_TOKEN`, `HIVE_DRIVE_TOKEN`,
  `HIVE_WORKSPACE`, else the app's socket and the person's token) are the SDK's `places.ts`. The
  CLI's `hcp.sock` client takes its token from there too.
- **The wire** (hello, ids, answers, events singly or as a list, close, timeout) is the SDK's
  `connection.ts`. The CLI's `drive.ts` is now an adapter over it that turns an `ApiError` into
  the CLI's error with its exit code, so every `hive ctl` test covers the client too.
- **The jobs** (agents, frames, terminals) are `client.ts`: the method and its params in order,
  with the workspace's folder filled in. In Python, `calls.py` says each job's call once, and the
  sync and asyncio clients both make it.
- **The types** are `@hivemind/workspace-api`'s, not retyped: `call("agent.read", …)` is typed by
  its `methods.ts`. The npm build bundles them into one `index.d.ts`. Python's `types.py` names the
  fields a program reads most, as TypedDicts; it cannot import TypeScript.
- **One error class**: `ApiError` with `code`, the one `@hivemind/workspace-api/protocol` already
  throws. A code a newer host sends is kept as it was sent.

## Python

Standard library only. The wire runs on asyncio (a Unix socket, or the app's named pipe through
the Windows proactor loop, which a blocking file handle cannot share between a reader and a
writer). The sync client runs that connection on a daemon thread of its own and waits on each
call, so there is one implementation of the protocol, not two. Listeners run on that thread.

## Tests

- `conformance/drive.json`: the drive socket message by message, written by hand from the spec,
  and where the socket is on each platform (the Windows pipe's hash taken with `sha256sum`). A
  fake host plays each case over a real local socket against each SDK.
- One live test per SDK: a real `hive host` from source with its own data folder and home, a grant
  made with `hive grant create`, `agent.list`, a `FORBIDDEN`, and `hive grant revoke` closing the
  connection. Every process it starts is stopped by its PID; the terminals' daemon, which outlives
  the host by design, by `hive daemon stop` on its own socket.

## How it ships

Not on npm or PyPI: the SDKs ship with the app, at its version (`scripts/release.sh` bumps
`packages/sdk/package.json` with the others and `hivemind_api.__version__` beside them).

- **Release assets.** `release.yml`'s `build-sdk` job builds `hivemind-api-<version>.tgz`
  (`build-npm.sh`, then `pnpm pack`, which applies `publishConfig`), and
  `hivemind_api-<version>-py3-none-any.whl` with its source `hivemind_api-<version>.tar.gz`; it
  installs and imports each before uploading. `publish` also copies them under names without the
  version, `hivemind-api.tgz` and `hivemind-api-python.tar.gz`, as it does the desktop builds, so a
  nightly's names are known too.
- **With the app.** `install.sh` and `install.ps1` fetch those two and put them in `sdk/` in the
  install folder (`~/.hivemind-app/sdk/`, `%LOCALAPPDATA%\hivemind\sdk\` on Windows):
  `hivemind-api.tgz`, and `python/`, the source unpacked, which `pip install` takes as a folder. A
  release without them installs the rest and says so, as one without hive-net does.

```sh
npm install ~/.hivemind-app/sdk/hivemind-api.tgz
npm install https://github.com/dip497/hivemind/releases/download/v<version>/hivemind-api-<version>.tgz
pip install ~/.hivemind-app/sdk/python
pip install https://github.com/dip497/hivemind/releases/download/v<version>/hivemind_api-<version>-py3-none-any.whl
pip install "git+https://github.com/dip497/hivemind#subdirectory=packages/sdk-python"
```
